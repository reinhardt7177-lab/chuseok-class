## 수업 전날 — 한 번만

```bash
npm install
```

삽화는 이미 `public/assets/img/`에 들어 있습니다. 다시 만들 일이 없다면 그대로 두세요.

## 수업 당일

### 1. 교사 PC에서 서버 켜기

```bash
npm start
```

창에 이렇게 뜹니다.

```
 교사용   http://localhost:8088/teacher.html
 학생용   http://10.177.40.53:8088/student.html
 입장코드 428701
```

**이 창을 수업이 끝날 때까지 닫지 마세요.** 닫으면 학생 응답이 모두 사라집니다.

### 2. 교사 화면 띄우기

브라우저에서 `http://localhost:8088/teacher.html` 을 열고 <kbd>F11</kbd>로 전체화면.

| 키 | 하는 일 |
|---|---|
| <kbd>→</kbd> <kbd>←</kbd> <kbd>Space</kbd> | **한 컷씩** 넘기기 |
| <kbd>↓</kbd> <kbd>↑</kbd> | **장면 통째로** 건너뛰기 |
| <kbd>D</kbd> | 오른쪽 도구창 접기 |
| <kbd>F11</kbd> | 전체화면 |

한 화면에는 **문장 하나와 그림 한 장**만 나옵니다. 아이들이 한 번에 한 가지만 보게 하려는 것이고,
덕분에 글자를 프로젝터에서 읽을 수 있을 만큼 크게 키울 수 있었습니다.
장면 하나는 컷 4~11개로 이루어지고, 화면 아래 막대로 어디쯤인지 표시됩니다.
시간이 부족하면 <kbd>↓</kbd> 로 다음 장면으로 건너뛰세요.

### 3. 학생 들여보내기

오른쪽 도구창 → **접속** 탭에 QR 코드와 여섯 자리 번호가 뜹니다.
학생 기기를 **교실 와이파이에 연결**한 뒤 QR을 찍게 하세요.

QR이 안 되는 기기는 주소창에 `10.177.40.53:8088` 을 직접 치고 번호를 넣으면 됩니다.
(주소의 숫자는 교실마다 다릅니다. 접속 탭에 나온 것을 쓰세요.)

## 인터넷에 올리기

두 가지 방식이 있고, 되는 범위가 다릅니다.

| |GitHub Pages|교실 PC `npm start` / Render|
|---|---|---|
|오프닝 · 9장면 · 삽화 · 영상|○|○|
|활동 8종 · 소원 엽서 저장|○|○|
|입장 코드 · 학생 명단|✕|○|
|라이브 퀴즈 · 소원 벽 공유|✕|○|
|선생님마다 다른 방|—|○|

앱은 어느 쪽에 올라갔는지 스스로 알아내고 화면을 바꿉니다.
서버가 없으면 학생 화면은 입장 칸을 감추고 **혼자 해보기**를 앞에 내놓고,
교사 화면 마지막 장면은 입장 코드 대신 학생 화면 주소와 QR을 보여줍니다.

### 선생님마다 다른 방

주소 하나를 여러 선생님이 같이 써도 반끼리 섞이지 않습니다.
**선생님 화면을 열 때마다 방이 하나씩 생기고, 방마다 입장 코드와 QR이 다릅니다.**
A반에서 연 퀴즈는 A반 학생 화면에만 뜨고, 명단도 소원도 방 안에서만 모입니다.

이 앱에는 로그인이 없습니다. 대신 선생님 화면이 방을 열 때 받아 가는 긴 열쇠가
그 방의 주인 증표이고, 그 브라우저에만 저장됩니다. 학생에게 알려주는 것은
여섯 자리 코드뿐입니다. 새로고침해도 같은 방으로 돌아옵니다.

방은 메모리에만 있습니다. 서버를 다시 켜면(Render 무료 등급이 잠들었다 깨는 경우 포함)
열려 있던 방이 모두 사라지고 학생은 새 코드로 다시 들어와야 합니다.
수업 도중에는 서버를 끄지 마세요.

### GitHub Pages

`main`에 밀어 넣으면 [`.github/workflows/pages.yml`](.github/workflows/pages.yml)이
`public/` 폴더를 그대로 올립니다. 빌드 단계가 없습니다 — 번들러 없이
브라우저가 바로 읽는 ES 모듈로만 되어 있기 때문입니다.

저장소 **Settings → Pages → Source** 를 **GitHub Actions** 로 한 번만 바꿔 주세요.

Pages 는 push 할 때마다 **자동으로** 바뀝니다. (Render 는 그렇지 않습니다 — 아래 참고.)

### Render — 실시간 기능까지

<https://chuseok-class.onrender.com> 에 올라가 있습니다.

**자동 배포는 꺼져 있습니다.** `main`에 push해도 Render는 그대로이고(GitHub Pages만 바뀝니다),
Render에 올리려면 직접 `npm run deploy:render` 를 돌립니다. 까닭은 아래 두 절에 있습니다.

올리는 길은 두 가지입니다.
[`render.yaml`](render.yaml)이 들어 있으니 대시보드에서 **New → Blueprint** 로 이 저장소를 고르면 되고,
대시보드에 들어가기 싫으면 API 키를 `.env`에 넣고 `npm run deploy:render` 를 돌리면 됩니다.
`LEONARDO_API_KEY`는 넣지 않아도 됩니다. 삽화가 이미 저장소에 들어 있어서
수업 중에는 Leonardo를 부르지 않습니다.

### 수업 시간에는 올리지 않는다

Render에 올리면(배포하면) 서버가 다시 켜집니다. 방은 메모리에만 있으므로 **열려 있던 수업방이 모두 사라지고**
학생은 새 코드로 다시 들어와야 합니다. 그래서 **평일 한국 시간 08:30~15:00 에는 올리지 않습니다.**

```
npm run deploy:check            # 지금 올려도 되는 시간인지만 본다 (키도 인터넷도 필요 없음)
npm run deploy:render           # 올린다 — 수업 시간대에 돌리면 거절한다
npm run deploy:render -- --now  # 수업 시간 규칙을 알고도 올린다 (지금 올리라고 정했을 때만)
```

공휴일·방학은 따로 따지지 않습니다. 쉬는 평일에 막히면 `--now` 를 주면 됩니다.
시각 기준은 [`scripts/class-hours.js`](scripts/class-hours.js) 한 곳입니다.

### 요금 — 그림·음악은 GitHub Pages에서 내려받는다

Render는 한 달 **5GB까지 대역폭이 무료**이고 넘으면 GB당 $0.15 입니다. 학급 하나(교사 1 + 학생 25)가
그림·음악으로 약 383MB를 받습니다. 2026-09-23(추석 연휴 전 마지막 수업일)에 전국 학급이 한꺼번에 써서
이 서버가 하루 238GB를 내보냈고 약 $39 가 청구됐습니다. 그날 수업 시간에 배포가 15번 있었던 것도 보탰습니다 —
예전에는 배포마다 파일 버전표(ETag)가 바뀌어서, 접속 중이던 기기가 이미 본 그림도 처음부터 다시 받았습니다.

그래서 두 가지를 바꿨습니다.

1. **그림·음악은 이 서버가 내보내지 않습니다.** `/assets/…` 요청을 같은 경로의 GitHub Pages 로 돌려보냅니다
   ([`server/asset-host.js`](server/asset-host.js)). Render 에서만 켜지고, 교실 PC `npm start` 는 직접 줍니다.
   - 환경변수 `ASSET_BASE` 로 다른 곳(예: Cloudflare Pages)을 가리킬 수 있습니다. 빈 값(`ASSET_BASE=`)이면 끕니다.
   - Render 가 내보내는 것은 HTML·JS·CSS·API 뿐이라 학급 하나에 약 7MB 입니다 (예전 약 383MB — 빈 브라우저로 장면을 끝까지 넘기며 직접 잰 값).
2. **파일 버전표(ETag)를 파일 내용으로 만듭니다** ([`server/static-cache.js`](server/static-cache.js)).
   배포해도 안 바뀐 파일은 브라우저가 다시 받지 않습니다. 그림·음악은 Render 에서 한 시간 동안 묻지도 않습니다.

**Pages 가 안 열릴 때** 그림이 모두 깨지지 않게 길을 두 개 두었습니다.

- 서버가 2분마다(안 열릴 땐 30초마다) Pages 를 들여다보고, 안 열리면 그동안은 Render 가 직접 내보냅니다.
  대역폭이 다시 들지만 수업이 끊기는 것보다 낫습니다. 로그에 `⚠️ … 직접 내보냅니다` 가 남습니다.
- 학생·교사 화면도 그림이 안 뜨면 같은 주소에 `?local=1` 을 붙여 **한 번 다시** 받습니다
  ([`public/js/shared/asset-fallback.js`](public/js/shared/asset-fallback.js)). 학교 망이 github.io 를 막았거나
  Pages 가 한 기기에 요청을 거절할 때도 그림이 나옵니다.

GitHub Pages 에는 월 100GB 쯤의 권장 한도가 있습니다(넘으면 안내 메일이나 제한이 올 수 있고, 요금은 없습니다).
한도를 넘어 Pages 가 막히면 위 길로 Render 가 직접 내보내므로 **수업은 계속되지만 Render 요금이 다시 듭니다.**
전국 학급이 몰리는 날이 또 온다면 Cloudflare Pages(대역폭 무제한, 계정 필요)로 옮기세요.
그림을 올리고 `ASSET_BASE` 값 하나만 바꾸면 됩니다.

그림을 **같은 파일 이름으로 바꿨다면** `public/js/shared/asset-url.js` 의 `ART_VERSION` 을 올려 주세요.
이미 받아 간 기기가 새 그림을 바로 받습니다. 새 그림은 push 해서 Pages 배포(약 1분)가 끝나야 Render 판에서도 보입니다.

### 잠드는 것 다루기

무료 등급은 15분간 아무도 안 들어오면 잠들고, 다시 깨는 데 1분쯤 걸립니다.
**수업이 시작되면 학생 기기가 6초마다 서버를 부르므로 그 뒤로는 안 잡니다.**
깨워 둘 필요가 있는 것은 수업 직전 몇 분뿐입니다.

[`.github/workflows/wake.yml`](.github/workflows/wake.yml) 이
**평일 한국 시간 08:40~14:00 에 10분마다 깨워 둡니다.** 몇 교시에 하든 들어가는 시간대입니다.
그 밖의 시간에 수업한다면 저장소 **Actions → 수업 전 깨우기 → Run workflow** 를 누르세요
(휴대폰 브라우저에서도 눌립니다).

시간대를 바꾸려면 `wake.yml` 의 `cron` 세 줄을 고치면 됩니다.
1교시만 쓰려면 첫 줄만 남기고(월 20시간), 더 늦게까지 쓰려면 `*/10 0-4` 의 `4`를 키웁니다.

## 문제가 생기면

**학생이 "입장 코드가 맞지 않아요"** — 서버를 다시 켜면 코드가 바뀝니다. 접속 탭의 현재 코드를 확인하세요.

**학생 기기에서 주소가 안 열림** — 같은 와이파이인지 먼저 확인하세요. 학교망이 기기 간 통신을 막아둔 경우도 있는데, 그때는 **혼자 해보기** 모드로 진행하면 됩니다.

**화면이 멈춘 것 같음** — 왼쪽 위 점이 초록이면 연결된 상태입니다. 빨강이면 서버 창이 살아 있는지 확인하세요.

**처음부터 다시** — 접속 탭 → 수업방 새로 열기. 새 코드가 나오고 모인 응답이 모두 지워집니다.

## 삽화를 다시 만들려면

`.env`에 Leonardo.Ai API 키가 필요합니다.

```bash
npm run key:check                    # 키와 남은 크레딧 확인
npm run assets:dry                   # 무엇을 몇 크레딧에 만들지 미리보기
npm run assets                       # 없는 것만 생성
node scripts/generate-assets.js --force --only opening-moonrise   # 한 장만 다시
node scripts/generate-assets.js --section food                    # 특정 장면만
```

73장에 약 590크레딧(1크레딧 ≈ $0.0015)이 듭니다. 이미 받은 그림은 건너뛰므로 중간에 끊겨도 다시 돌리면 이어서 받습니다.

프롬프트를 고쳤다면 브라우저용 색인도 다시 만드세요.

```bash
node scripts/build-asset-index.js
```

유튜브 영상이 아직 살아 있는지 확인하려면:

```bash
node scripts/check-videos.js
```

## 구조

```
server/
  server.js        Express + SSE. 수업 중 외부 API를 부르지 않는다.
  classroom.js     수업방 상태 (메모리). 서버를 끄면 초기화된다.
  leonardo.js      Leonardo.Ai 클라이언트 (삽화 생성 전용)

public/
  index.html       교사 / 학생 갈림길
  teacher.html     전체 학습 — 프로젝터용
  student.html     개별 학습 — 태블릿·크롬북용
  js/data/         수업 내용 단일 원본 (lesson · quiz · activities · videos)
  js/shared/       무대 연출 · 삽화 색인 · 결과 카드 생성
  assets/img/      삽화 73장

scripts/
  asset-manifest.js   삽화 목록과 프롬프트
  generate-assets.js  일괄 생성기
  check-videos.js     유튜브 생존·임베드 확인
```

수업 내용을 고치려면 `public/js/data/lesson.js` 하나만 보면 됩니다.
교사 화면과 학생 화면이 이 파일을 함께 읽습니다.
